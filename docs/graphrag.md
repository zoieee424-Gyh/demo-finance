# GraphRAG 壳子说明

## 它可以用在什么地方

GraphRAG 适合用在“单纯向量相似度不够，需要关系推理”的金融问题中，例如：

- 财报分析：公司、财务指标、行业、风险事件之间的关联分析。
- 风控审查：风险因子、资产类别、投资组合、风险暴露之间的路径追踪。
- 监管合规：法规条款、违规表达、适当性要求、风险披露义务之间的关系匹配。
- 智能投顾：用户目标、风险等级、资产类别、配置原则之间的结构化关联。
- 金融科普：概念之间的前置知识、从属关系和学习路径推荐。

## 它的作用

普通 RAG 主要依赖向量相似度，擅长找到“语义相近”的文本。GraphRAG 的重点是把知识组织成“实体-关系-路径”的结构，帮助系统回答：

- 某个风险和哪些资产、指标、法规有关？
- 某条合规要求限制了哪些表达？
- 某个财务异常可能连接到哪些风险事件？
- 用户问题需要沿着哪些概念关系展开解释？

在本项目中，GraphRAG 的定位是 RAG 增强层：

```text
用户问题
  -> 语义检索 Chroma
  -> BM25 稀疏检索 / Hybrid 混合检索
  -> GraphRAG 图谱扩展
  -> Evidence Pack
  -> DeepAgent 报告生成
```

## 当前实现状态

已实现：

- `backend/app/rag/graph_retriever.py`
- `GraphRAGRetriever`
- `GraphRAGQueryContext`
- `FIN_AGENT_GRAPHRAG_ENABLED` 配置开关
- `KnowledgeRetriever` 中的 GraphRAG 可选扩展入口
- 单元测试覆盖 import、空返回、fake graph_store 转 Source

尚未实现：

- 社区发现
- 图路径检索

## 后续可接入方案

轻量方案：

- MySQL 表存储实体和关系。
- NetworkX 在内存中构建图。
- 适合课程演示和小规模知识库。

工程方案：

- Neo4j / NebulaGraph 存储图谱。
- 从知识库 chunk 中抽取实体和关系。
- 查询时进行实体链接、路径扩展、社区摘要，再与 Chroma/BM25 结果融合。
