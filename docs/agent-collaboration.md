# Agent Collaboration Protocol

## 1. 总控原则

Codex 是项目总监，负责：
- 明确目标、范围、优先级和验收标准。
- 拆分任务并决定是否派给 Claude Code 或 DeepSeek v4 pro。
- 审查所有产出，必要时亲自修改。
- 维护 `CLAUDE.md`、`MEMORY.md` 和关键项目文档。

唯一执行员工：
- Claude Code，且 Claude Code 搭载 DeepSeek v4 pro 作为 LLM。
- 后续提到“员工”时，均指这个 Claude Code + DeepSeek v4 pro 的组合体。

执行员工适合：
- 架构方案、多方案对比、复杂业务规则梳理。
- Agent/RAG 流程设计、提示词设计、数据结构草案。
- 直接修改仓库代码、跑测试、修 bug、补文档。
- 输出可验证的工程实现、测试用例清单、风险清单。

执行员工的产出必须经过 Codex 验收：
- Codex 负责最终方向、架构裁剪、质量门禁和合入判断。
- 员工不得擅自改变项目方向、核心技术栈或金融合规边界。

## 2. 派工标准

适合派给员工的研究/设计任务：
- 需求还不清，需要业务拆解。
- 一个模块有多种实现路径，需要权衡。
- 需要写复杂 prompt、agent profile、RAG planner、evaluation rubric。
- 需要生成一版可供 Claude Code 实现的详细规格。

适合派给员工的实现任务：
- 需要读当前代码并修改文件。
- 需要跑命令、处理依赖、调试错误。
- 涉及多个文件集成、测试修复、最终验收。

必须由 Codex 先审再派或亲自处理的任务：
- 涉及安全、合规、数据模型迁移等高风险变更。
- 新增重依赖、改变技术栈、改变项目范围。
- 影响全局架构或验收口径。

## 3. 员工派工单模板

```markdown
你是本项目唯一执行员工：Claude Code，搭载 DeepSeek v4 pro 作为 LLM。
你的上级是项目总监 Codex。

项目背景：
- 项目：基于 Agentic RAG 与多智能体协作的智慧金融服务平台
- 核心模块：智能投顾、财报分析、风控审查、监管合规、金融科普
- 合规红线：不荐股、不预测涨跌、不承诺收益；投资相关输出必须有风险提示和依据来源

你的任务：
【写清楚一个具体任务，不要多任务混杂】

已知约束：
- 技术栈：LLM 使用云端 API（具体 Provider 由用户告知）；向量库使用 Chroma，先做基础语义检索，后续可预留 BM25 混合检索；其余技术栈按现有架构和任务需要选择
- 输出要能交给 Claude Code/Codex 落地
- 不要假设你能直接访问最新仓库文件

请按以下格式输出：
1. 目标重述
2. 推荐方案
3. 数据结构/接口/流程设计
4. 关键算法或提示词草案
5. 验收标准
6. 风险与反例
7. 需要 Codex/Claude Code 落地的文件或模块建议
```

## 4. 员工回传验收表

员工的结果回传给 Codex 后，Codex 按下面标准验收：

- 是否回答了派工单里的具体问题。
- 是否可落地到当前技术栈。
- 是否没有越过金融合规红线。
- 是否包含数据来源、风险、失败场景。
- 是否足够具体，Claude Code 能据此改代码。
- 是否引入不必要的新依赖或过度设计。

不合格则返工，返工单必须指出：
- 哪一节不合格。
- 缺少什么信息。
- 需要保留什么、推翻什么。

## 5. Codex 调度流程

1. Codex 先读当前项目上下文与 `MEMORY.md`。
2. Codex 判断任务类型：实现、研究、设计、验证、修复。
3. 若适合员工执行，Codex 生成可复制派工单给用户转交。
4. 用户把员工输出贴回。
5. Codex 做审查、裁剪、改写为工程任务。
6. Codex/Claude Code 实现并测试。
7. Codex 更新 `MEMORY.md` 中的新决策和坑点。

## 6. 默认分工建议

MVP 阶段：
- 员工：负责智能体职责、RAG流程、合规提示词、评估标准、项目骨架、API、前端页面、测试、运行脚本。
- Codex：负责架构裁剪、接口统一、最终验收。

拔高阶段：
- 员工：负责财报指标模型、风控模型、合规规则库设计、PDF 解析、向量库接入、图表展示、历史记录。
- Codex：负责性能、质量门禁、端到端验收。
